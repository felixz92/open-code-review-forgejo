# ocr-forgejo: Go CLI posting OpenCodeReview results to Forgejo PRs

Port of [alibaba/open-code-review](https://github.com/alibaba/open-code-review)'s
`examples/gitlab_ci/post_review.py` CI glue, targeting Forgejo instead of GitLab.
Reads the JSON emitted by `ocr review --format json` and posts it to a pull request.

**Execution model: spec-driven via OpenSpec.** This plan maps onto one change,
`add-ocr-forgejo-cli`, broken down into the artifacts below. The work happens
from that change (`/opsx-apply`), never ad-hoc.

## Confirmed decisions

| Decision | Choice |
|---|---|
| Posting model | **One review per run** — `CreatePullReview` with all inline comments + `SubmitPullReview` (event `COMMENT`). Must be documented in an ADR. |
| Runtime | **Argo Workflows**. Token from `GIT_TOKEN` env (bot identity `GIT_USER` available). All targeting via **required flags**: `--url`, `--repo owner/name`, `--pr <index>`, input path. No Forgejo Actions / env auto-detection. |
| SDK | `codeberg.org/mvdkleijn/forgejo-sdk/forgejo/v3` (user confirmed v3, latest). |
| Summary | **Sticky issue comment** carrying `<!-- ocr-summary -->` marker, updated in place via `EditIssueComment`. Review body empty/one-liner. |
| Module / binary | module `github.com/felixz92/open-code-review-forgejo`, binary `ocr-forgejo` in `cmd/ocr-forgejo`. |
| Feature scope | Full port incl. incremental IoU overlap and publication-policy routing (both opt-in flags, defaults matching the Python script). |

## Semantic mapping (GitLab script -> Forgejo)

- Positional discussion -> `CreatePullReviewComment{Path, Body, NewLineNum: end_line}`. No multiline ranges exist; anchor at `end_line`, state the span (L10-L14) in body.
- `commit_id` on `CreatePullReviewOptions` = OCR manifest `manifest.input.resolved_head` (fallback: PR head SHA from `GetPullRequest`). Guards against force-push drift (replaces GitLab `/versions` SHA matching).
- Idempotency: before creating, list reviews (`ListPullReviews`), delete stale **pending** reviews authored by the bot (`DeletePullReview`); a failed submit leaves a pending review that gets deleted and retried whole. Per-comment `<!-- ocr-<runtag>-<rand> -->` tags kept for incremental history detection.
- Sticky summary: PR == issue -> `ListIssueComments` / `CreateIssueComment` / `EditIssueComment` with `SUMMARY_MARKER = <!-- ocr-summary -->` plus per-run `<!-- ocr-summary-run:TAG -->`.
- Diff-inventory pre-check: fetch `GetPullRequestDiff` (or `ListPullRequestFiles`), parse unified-diff hunks, classify each comment valid/invalid/unknown **before** submitting; drop provably-out-of-diff (record reason), keep unknown.
- Suggestions: no `suggestion:` blocks in Forgejo -> plain fenced Before/After in comment body.
- Rate limiting: Forgejo has none by default. Drop wait-until-reset and read-pacing; keep simple retry with exponential backoff + jitter on 429/5xx/network errors (max 3).

## CLI surface (draft)

```
ocr-forgejo --url https://forge.example.com --repo owner/name --pr 42 \
  [--input .ocr/ocr-result.json] [--stats-file .ocr/ocr-stats.env] \
  [--dry-run] [--sticky-summary=true] [--incremental=false] \
  [--incremental-overlap-threshold=0.6] \
  [--route-severity-below ""] [--route-categories ""] \
  [--fail-on-severity ""] [--stderr-log .ocr/ocr-stderr.log]
```

Token: `GIT_TOKEN` env (required unless `--dry-run` should still require it? — decide: required always, fail fast if unset). Run tag for idempotency ids: derived from PR index + head SHA (no CI env available on Argo by default; make `--run-tag` optional override).

## Repository layout

```
cmd/ocr-forgejo/main.go        flag parsing, wiring, exit codes
internal/review/               parse OCR result JSON (comments, warnings, manifest)
internal/format/               badges, comment bodies, fallback formatting, fences,
                               warnings, summary body builders  (pure, port of Python)
internal/policy/               build_policy / route_comment (pure)
internal/incremental/          comment_span, IoU overlap, history loading (pure + SDK)
internal/diffinv/              unified-diff hunk parsing + classification (pure)
internal/poster/               Poster interface + ForgejoPoster (SDK transport)
                               + DryRunPoster
internal/publish/              orchestration: partition, sort, filter, post, summary,
                               stats (port of publish())
docs/adr/0001-single-review-posting.md
```

Port the Python's separation of pure logic (unit-testable without network) from transport; the `Poster` interface pattern carries over directly.

## Output JSON fields consumed (from post_review.py)

`comments[]{path, start_line, end_line, content, suggestion_code, existing_code, category, severity}`,
`warnings[]{file, type, message}`, `message`, `manifest.input.resolved_head`, `manifest.input.resolved_base`.

## Tasks (ordered)

1. `go mod init github.com/felixz92/open-code-review-forgejo`; add SDK v3 dependency; scaffold `cmd/ocr-forgejo/main.go` with flag set + config struct.
2. Write `docs/adr/0001-single-review-posting.md`: context (GitLab per-discussion vs Forgejo review primitive), decision (one review per run), consequences (atomic submit, delete-stale-pending idempotency, no per-finding threads, multiline anchors at end_line). User explicitly required this ADR.
3. `internal/review`: result JSON structs + loader (tolerant: missing fields -> zero values, as Python `.get`).
4. `internal/format`: port badge, `format_comment` (id tag + badge + content + Before/After fences, no suggestion blocks), `format_comment_fallback` (details/summary collapsible), warnings, `build_summary_body`, pre-review body, fence-length safety.
5. `internal/policy` + `internal/incremental` + `internal/diffinv`: port pure logic incl. `comment_span`, `same_comment_span` (IoU, strict >), `parse_diff_hunk_inventory`, `build_new_line_positions` (not needed for line_code — drop; only ranges/known-files matter), classification tri-state.
6. `internal/poster`: `Poster` interface (PostReview, DeletePendingReviews, ListReviews, ListReviewComments, CreateIssueComment, EditIssueComment, ListIssueComments, GetPullRequestDiff, PRURL) + `ForgejoPoster` over SDK v3 with retry/backoff + `DryRunPoster`.
7. `internal/publish`: port `publish()` flow — partition (inline / no-line / routed), deterministic sort, incremental filter, diff-inventory pre-check, delete stale pending reviews, create+submit review, sticky summary anchor/finalize, stats.
8. Stats `.env` writer, `--fail-on-severity` gating, exit codes (0 ok, non-zero on hard failure or severity gate).
9. Unit tests for every pure package (mirror the Python behaviors: ordering, IoU boundary, tri-state classification, fence safety, sticky find-newest-first). Integration test of `publish` against a fake `Poster`.
10. README: usage from Argo Workflows (GIT_TOKEN, flags), example workflow step.

## Validation

- `go vet ./...`, `go test ./...` green.
- `--dry-run` against a real `.ocr/ocr-result.json` fixture prints review comments + summary instead of posting.
- Optional manual smoke against a real Forgejo instance with a scratch PR: run twice, confirm sticky summary updates in place and no duplicate reviews; run with an out-of-diff line, confirm pre-check drops it with reason; run with `--incremental` after adding an overlapping finding, confirm skip.

## Risks / open items

- SDK v3 API surface assumed identical in shape to v2 (review types, issue comments, PR diff). Verify at task 6; v3 pkg.go.dev link: codeberg.org/mvdkleijn/forgejo-sdk/forgejo/v3.
- `GetPullRequestDiff` returns a raw unified diff (bytes) — enough for `diffinv`; `ListPullRequestFiles` is the fallback if binary/whitespace options complicate parsing.
- Empty-body review submit with only comments: verify Forgejo accepts `SubmitPullReview` with empty body; if not, put a one-line summary in the review body.
- Argo injects `GIT_USER` but SDK auth is token-only; `GIT_USER` is informational (logging) unless needed for bot detection — bot detection uses the authenticated user via `GetMyUserInfo` when deleting pending reviews.
